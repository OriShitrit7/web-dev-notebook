## הרצה מקומית

**לחיצה כפולה על `start.command`** בתיקיית הפרויקט. זה מרים שרת מקומי ופותח את
הדפדפן אוטומטית. לעצירה: `Ctrl+C` או סגירת חלון ה־Terminal שנפתח.

לחלופין, ידנית:

```bash
python3 -m http.server 8000
```

ואז לפתוח `http://localhost:8000`.

> אם שינויים לא מופיעים אחרי רענון — זה cache של הדפדפן. רענון קשיח:
> `Cmd+Shift+R` (macOS) או `Ctrl+Shift+R` (Windows).

### למה צריך שרת ולא פשוט לפתוח את index.html?

שתי סיבות, ושתיהן לא ניתנות לעקיפה בלי לשנות את מבנה הפרויקט:

1. **`fetch` חסום ב־`file://`.** `app.js` טוען את הפרקים בזמן ריצה
   (`fetch('content/html/overview.md')`). כשפותחים קובץ בלחיצה כפולה הדפדפן
   מתייחס אליו כ־origin אטום וחוסם קריאה לקבצים שכנים — הגנת אבטחה, לא באג.

2. **הספריות מגיעות מ־CDN.** `index.html` טוען את `marked` (שממיר את ה־Markdown
   ל־HTML) ואת `highlight.js` מרשת. בלי `marked` הדף יישאר ריק, גם אם סעיף 1 היה נפתר.

בפועל זה לא מפריע: **ב־GitHub Pages הכול עובד רגיל**, כי שם האתר מוגש ב־HTTP.
השרת המקומי נחוץ רק כדי לראות שינויים *לפני* שדוחפים אותם.

#### דמו של JavaScript — פאנל ה־Console

דמו שכולו **בלוק `<script>` יחיד** מטופל אחרת, וזה מה שפרקי JavaScript משתמשים בו:

- תווית החלונית תהיה **JS** במקום HTML, ותגיות ה־`<script>` **לא יוצגו** בקוד
  (גם כפתור ה־Copy מעתיק רק את ה־JavaScript עצמו).
- כל קריאה ל־`console.log` / `warn` / `error`, וכן **שגיאה לא מטופלת**,
  מוצגת ב**פאנל שחור מתחת לתצוגה** — כי אחרת הפלט היה נעלם ב־Console של הדפדפן
  והקוראת לא הייתה רואה כלום.
- הפאנל מופיע **רק אם הדמו באמת הדפיס משהו**. דמו בלי פלט נראה כרגיל.
- פלט שמגיע מאוחר (למשל מתוך `setTimeout`) מרחיב את ה־iframe אוטומטית.

````markdown
```demo
<script>
  console.log("hello", 42);
</script>
```
````

> **שימי לב:** דמו שמערבב `<script>` עם HTML — או שיש בו **שני** בלוקי script —
> נשאר דמו HTML רגיל. הזיהוי דורש בלוק script **יחיד** שעוטף את כל הדמו.

### שאלון בסוף פרק — ```quiz

בלוק קוד עם השפה `quiz` הופך לשאלון אמריקאי אינטראקטיבי: לחיצה על תשובה
מסמנת מיד נכון/שגוי, חושפת את ההסבר, ומעדכנת ניקוד. בסוף יש כפתור התחלה מחדש.

````markdown
```quiz
? נוסח השאלה, אפשר עם `code`
- מסיח שגוי
+ התשובה הנכונה
- עוד מסיח
= ההסבר שמוצג אחרי הבחירה
```
````

| סימן | משמעות |
| --- | --- |
| `?` | פותח שאלה חדשה |
| `+` | התשובה הנכונה — **בדיוק אחת לכל שאלה** |
| `-` | מסיח שגוי |
| `=` | ההסבר |

- הנוהג באתר: **5 שאלות לפרק, 4 אפשרויות לכל שאלה**, תחת כותרת `## בדקי את עצמך`.
- שאלה בלי `+`, או עם פחות משתי אפשרויות, **לא תוצג כלל** — כך שגיאת כתיבה
  לא שוברת את הפרק אלא רק מעלימה את השאלה.
- סימון התשובה הנכונה לא מוסתר בקוד המקור. זה בסדר — השאלון נועד לעזור לך
  לבדוק את עצמך, לא למנוע העתקה.

### בלוקים

> **כלל הזהב של הפרק:** חוץ מכותרות ומפסקת ה־`lead` בראש הפרק, **שום טקסט לא יושב
> ישירות על רקע האתר**. כל פסקה נמצאת בתוך `box` כלשהו. זה מה שעושים גם בדשבורד ה־DS/ML.
> לפסקה רגילה בלי כותרת משתמשים ב־`box` בלי `box-head`:
>
> ```html
> <div class="box">
>   <div class="box-body">
>     <p>הטקסט כאן.</p>
>   </div>
> </div>
> ```

| רכיב | שימוש |
| --- | --- |
| `<p class="lead">` | פסקת פתיחה לפרק — **הדבר היחיד שמותר לו להיות בלי מסגרת** |
| `<div class="box">` | פסקה רגילה במסגרת, בלי כותרת |
| `<div class="box theory">` | הגדרה / תיאוריה (כחול) |
| `<div class="box example">` | דוגמה / תובנה (ירוק) |
| `<div class="box warn">` | אזהרה / טעות נפוצה (אדום) |
| `<div class="box rule">` | כלל (כתום) |
| `<div class="box summary">` | סיכום פרק (אפור) |
| `<div class="keypoint">` | שורת הדגשה עם 💡 |
| `<p class="note-line">` | הערת שוליים קטנה ואפורה |
| `<div class="figure">` | איור (SVG או תמונה) + `<div class="cap">` לכיתוב |
| `<div class="compare">` | השוואה בשני טורים: `<div class="good">` ו־`<div class="bad">` |

מבנה של `box`:

```html
<div class="box theory">
  <div class="box-head"><span class="icon">📘</span>הכותרת</div>
  <div class="box-body">
    <p>התוכן.</p>
  </div>
</div>
```

מבנה של `compare`:

```html
<div class="compare">
  <div class="good">

  </div>
  <div class="bad">
```
